# R&D 성과구조 진단 도구 (rnd-profiler)

공공 R&D 집계 CSV(사업별 투입·논문·특허)를 넣으면 표를 정리해 주는 데서 끝나지 않고, **어디를 더 들여다볼지 판단하는 근거**를 한 화면에 보여 주는 도구입니다. 서버·AI·API 키가 없고, 모든 계산은 브라우저(또는 Node 테스트) 안에서 규칙대로만 이뤄집니다.

정책 담당자가 개선을 점검할 사업과 더 살펴볼 사업을 고를 때 참고 자료로 쓰는 것을 염두에 두었습니다. 도구는 후보와 근거 숫자까지만 보여 주고, 무엇을 고칠지·늘릴지는 사람이 정합니다. 사업 평가나 순위가 아닙니다.

한양대 과학기술정책학과 「과학기술정책 연구도구」 과제 ⑤ 연구·R&D 데이터 대시보드 유형입니다. 흐름은 `내 자료(붙여넣기·CSV) → 기준 파일(프로필) → 한눈에 보기·표·그래프 → 내보내기(CSV·마크다운)`입니다.

- 저장소: <https://github.com/LUKE-BJ/rnd-profiler>
- 접속 주소(GitHub Pages를 켠 뒤): <https://luke-bj.github.io/rnd-profiler/>
- 변경 기록: [CHANGELOG.md](CHANGELOG.md) (현재 v0.3.0)

## 화면에서 보는 순서

| 섹션 | 답해 주는 질문 |
|---|---|
| **한눈에 보기** | 숫자에서 바로 읽히는 비교는 무엇인가. 규칙으로 채운 문장(투입 집중 대비 성과 집중, 유형, 점검 후보, 확대 검토 후보, 분모 작음, 과제 수 적음, 후보 안정성). 원인·우열은 쓰지 않습니다. |
| **빠진 것** | 이 결과는 전체의 몇 %를 본 것인가. 행·과제·논문·특허의 분석 포함 비율과, 제외된 행 중 성과가 있는 행 |
| 검산 | 합계가 맞는가. 원본 합계 = 분석 대상 + 제외, 집계표 합계 = 원본 합계 |
| 요약·산점도 | 투입과 성과 밀도는 어떻게 흩어져 있는가 |
| **점검 후보** | 투입은 큰데 밀도가 낮은 행(개선 점검 쪽). 기준을 옮겨도 계속 잡히는지(점검 유지 n/25)를 함께 보여 줍니다. |
| **확대 검토 후보** | 투입은 작은데 밀도가 높은 행(더 살펴볼 쪽). 분모 작음 행은 뒤에 두고, 확대 유지 n/25를 함께 보여 줍니다. |
| 집계표·전체 지표표·제외 행 | 사업별 값, 정렬해서 훑기, 계산에서 빠진 행 |

## 읽을 때 주의

- **분모 작음.** 투입이 작은 행은 논문·특허 몇 건만 늘어도 밀도가 크게 달라집니다. 투입 하위 25% 행에 표시를 붙였고, 확대 검토 후보에서는 이 행을 뒤에 둡니다. 표시만 붙이고 지표에서 빼지는 않습니다.
- **과제 수 적음.** 과제 수가 3개 이하인 행은 한두 과제의 성과에 밀도가 좌우됩니다. 과제 수 컬럼이 있을 때만 표시하고, 기준 개수는 바꿀 수 있습니다.
- **후보 안정성.** 후보 기준은 정해진 값이 아니므로, 두 기준을 각각 ±5%p, ±10%p씩 옮긴 25가지에서 몇 번 잡히는지를 셉니다. n/25가 낮은 행은 기준에 따라 잡히거나 빠지는 행이고, 같은 25가지에서 후보 수가 얼마나 달라지는지도 한눈에 보기에 나옵니다.
- **빠진 것.** 투입이 0이거나 비어 있는 행은 밀도를 계산할 수 없어 지표에서 빠지지만 합계에는 남습니다. 포함 비율이 낮으면 결과는 전체의 일부만 본 것입니다.
- **기준값은 제안값입니다.** 점검 후보(투입 상위 25%·밀도 하위 40%), 확대 검토 후보(투입 하위 50%·밀도 상위 25%), 분모 작음(투입 하위 25%)과 과제 수 적음(3개 이하)은 근거가 있는 수치가 아니라 시작점입니다. 화면의 '판정 기준값 조정'에서 바꾸면 바로 다시 계산합니다.

## 쓰는 법

1. `index.html`을 브라우저로 엽니다(더블클릭으로 충분합니다). GitHub Pages로 올려도 같습니다. 파일 하나만 필요하면 `dist/rnd-profiler.html`을 쓰세요.
2. **KEIT 예시 불러오기**를 누르거나, CSV를 고르거나, 표를 붙여 넣고 **분석하기**를 누릅니다.
3. 컬럼이 맞는 기준(프로필)이 자동 선택됩니다. 맞는 프로필이 없으면 **컬럼 직접 지정**에서 역할과 투입 단위(억원·백만원 등)를 지정하면 새 프로필이 만들어지고 JSON으로 내려받을 수 있습니다. 컬럼 이름에 단위가 없으면 단위 칸이 비어 있고, 입력해야 분석됩니다.
4. 맨 아래 **저장**에서 `out.zip`(결과 8개 파일), 폴더 저장(Chrome·Edge), 요약 복사를 고릅니다. 정적 페이지는 컴퓨터 폴더에 직접 쓸 수 없어 이렇게 제공합니다.
5. 같은 계산을 명령줄로도 돌립니다: `node tests/check_expected.js` (예시 입력 → `out/` 저장 → 기대 결과와 비교).

## 가져가서 쓰기

설치할 것이 없습니다. Node.js는 `tests/`와 `tools/`를 돌릴 때만 필요하고, 화면은 브라우저만 있으면 됩니다.

| 하고 싶은 일 | 방법 |
|---|---|
| 그냥 써 보기 | `dist/rnd-profiler.html` 한 파일만 내려받아 브라우저로 엽니다 |
| 저장소 통째로 받기 | `git clone` 또는 GitHub의 Code → Download ZIP |
| 내 기관 자료에 맞추기 | `profiles/`에 JSON을 하나 추가합니다(컬럼 역할은 아래 표). 화면의 **컬럼 직접 지정**으로 만든 JSON을 넣어도 됩니다 |
| 고친 뒤 확인하기 | `node tools/build.js`(내장 데이터·단일 HTML 재생성) → `node tests/check_expected.js` |

`js/data.js`와 `dist/rnd-profiler.html`은 `tools/build.js`가 만드는 파일이므로 직접 고치지 않습니다.

## 기준 파일(프로필)

컬럼 이름과 기준값은 코드에 박혀 있지 않고 `profiles/*.json`에 있습니다. 다른 기관 자료는 프로필만 추가하면 됩니다(`sample_other_org.json`은 컬럼명·단위가 다른 가상 예시).

| 항목 | 뜻 |
|---|---|
| `columns.input` | 투입(출연금·연구비). 필수 |
| `columns.count` | 과제 수(과제당 평균 계산) |
| `columns.paper` / `patent` | 논문·특허 컬럼(여러 개면 합산) |
| `columns.group` | 집계표 기준 그룹 |
| `columns.label` | 행 이름으로 쓸 컬럼 |
| `columns.year` | 연도(값이 2개 이상일 때만 추이 표시) |
| `units.input` / `densityPer` | 투입 단위 표기, 밀도 기준(예: 출연금 10억원당) |
| `thresholds` | 유형·점검 후보·확대 검토 후보·분모 작음·집중도 기준값 (화면에서도 조정 가능) |

필요한 컬럼이 없으면 그 지표만 자동으로 꺼지고, 어떤 기능이 꺼졌는지 화면과 `run_meta.json`에 적힙니다.

## 지표 정의

- **과제당 평균 투입** = 투입 ÷ 과제 수
- **논문 밀도 / 특허 밀도 / 복합 밀도** = (논문 / 특허 / 논문+특허) ÷ 투입 × 기준(예: 10억원)
- **성과 유형**: 논문 비중 ≥ 65% 논문형, ≤ 35% 특허형, 그 사이 균형형, 성과 0이면 성과 없음
- **점검 후보**: 투입 상위 25% 이면서 복합 밀도 하위 40%. 유형과 독립이며 부실 판정이 아니라 추가 확인 대상
- **확대 검토 후보**: 투입 하위 50% 이면서 복합 밀도 상위 25%. 확대를 권하는 것이 아니라 추가 확인 대상
- **분모 작음**: 투입 하위 25%인 행
- **과제 수 적음**: 과제 수가 3개 이하인 행(과제 수 컬럼이 있을 때만)
- **후보 안정성(유지 횟수)**: 점검·확대 후보의 두 기준을 각각 ±5%p, ±10%p씩 옮긴 5×5=25가지 중 후보로 잡힌 횟수. 가운데 칸이 현재 기준이라 현재 후보는 최소 1회입니다. 기준이 1%~99% 범위를 넘으면 가장자리 값으로 고정합니다.
- **한눈에 보기**: 위 값에서 고정 문장 틀에 숫자만 채운 관찰문. 숫자 비교만 적고 원인·우열은 쓰지 않습니다.
- **빠진 것**: 분석에 포함된 비율(행·과제·논문·특허)과 제외 행 중 성과가 있는 행 수
- **집중도**: 투입 상위 10% 행의 비중, 누적 곡선, 지니계수
- **검산**: 이중 집계 의심(같은 연도·그룹·항목 중복)과 숫자로 읽히지 않은 칸도 표시
- 분위수는 선형보간(exclusive) 방식입니다.

## 예시 자료와 출처

- `examples/input_keit_2024.csv`: 한국산업기술기획평가원(KEIT) 「산업기술 연구개발 성과조사정보」 2024.12.31 기준, 268행. 공공데이터포털 <https://www.data.go.kr/data/15105259/fileData.do>, 이용허락범위 제한 없음. 원본 그대로이며 개인정보가 없는 집계 자료입니다.
- `examples/input_other_org.csv`: 범용성을 보이기 위해 만든 **가상** 자료입니다.

KEIT 예시를 돌렸을 때 나오는 값입니다(측정값이며 좋고 나쁨의 판단이 아닙니다).

| 항목 | 값 |
|---|---|
| 분석 대상 / 전체 | 107행 / 268행 (제외 161행 중 성과가 있는 행 74) |
| 분석 포함 비율 | 행 39.9%, 과제 70.2%, 논문 94.9%, 특허 88.5% |
| 투입 합계 / 유형 분포 | 15,938억원 / 논문형·균형형·특허형·성과 없음 = 59·21·12·15행 |
| 투입 상위 10%(11행) 비중 | 투입 68.6%, 논문 56.6%, 특허 57.4% (지니계수 투입 0.790) |
| 점검 후보 | 6행 |
| 확대 검토 후보 | 16행, 그중 분모 작음 10행 |
| 복합 밀도 상위 10%(11행) 중 분모 작음 | 7행 |
| 과제 수 3개 이하 | 31행(분석 대상의 29.0%), 점검 후보 중 0행·확대 검토 후보 중 6행 |
| 점검 후보의 유지 횟수 | 25가지 모두 잡히는 행 1(스마트카), 나머지 9~15회. 같은 25가지에서 점검 후보 수 1~15행 |
| 확대 검토 후보의 유지 횟수 | 25가지 모두 잡히는 행 11, 같은 25가지에서 후보 수 11~25행 |

테스트(`tests/check_expected.js`)는 예시 결과를 `examples/expected/`와 바이트 단위로 비교하고, 핵심 수치(행 수·합계·유형·점검 후보·집중도·지니계수)를 별도로 계산한 값과 대조합니다. 분모 작음·확대 검토 후보·포함 비율·과제 수 적음은 손으로 계산한 작은 표와, 테스트 안에서 코어와 따로 센 값으로 확인합니다. 후보 안정성은 코어와 따로 짠 반복문과, 기준을 바꿔 계산을 25번 돌린 값으로 대조합니다.

## 한계

- 탐색적 선별 도구이며 사업 평가·순위가 아닙니다.
- 성과는 시차를 두고 나타나므로 같은 해 투입과 성과를 바로 대응시키면 왜곡됩니다. 한 해 자료만으로는 투입을 늘렸을 때 성과가 어떻게 달라지는지 알 수 없습니다.
- 사업 목적(원천·사업화·인프라)이 달라 논문·특허 밀도를 사업 간 우열로 읽을 수 없습니다. 낮은 이유가 비효율인지 사업 성격인지 이 도구는 구분하지 못합니다.
- 후보 안정성의 ±5%p·±10%p, 25가지 범위도 정한 값입니다. 이 범위 안에서 유지된다는 것이 맞는 후보라는 뜻은 아닙니다.
- 성과는 논문·특허만 봅니다. 기술이전, 사업화, 정책 파급은 들어 있지 않습니다.
- 집계 자료이므로 개별 과제를 추정할 수 없고, 입력 자료의 범위(예: KEIT 관리 산업기술 R&D)만 대표합니다.
- 보조 컬럼(`aux`)은 합산하지 않고 그대로 둡니다(퍼센트·연수 합계는 의미가 없음).
- API 키·개인정보는 코드와 저장소에 없습니다.
